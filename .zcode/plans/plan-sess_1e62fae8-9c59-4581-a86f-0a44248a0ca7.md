# reasonix「运行一段时间触发最大限制」优化方案

## 诊断结论（已从本地最新二进制逐一核实键名与默认值）

| 机制 | 真实键名 | 默认行为 | 触发文案 |
| --- | --- | --- | --- |
| bedrock Run 超时 | `ai_agents.timeout_sec`（设置页「超时(秒)」） | **600s，到点杀进程** | run 直接失败 |
| 工具轮数上限 | CLI `--max-steps`（一次性 run）；`[agent].max_steps` 已废弃 | 不传 = 自动进度管理，长时间无新进展会 pause | `Your tool-call round limit (N) has been reached` / `paused after N tool-call rounds` |
| task 预算 | `task_time_budget_minutes` / `task_cost_budget` | 不设 = 不限制 | `This task has reached its %s budget` |
| Goal 预算 | `[agent].goal_token_budget`、goal 的 `max_goal_rounds` | 不设 = 无限制 | `goal exhausted its configured round limit` |
| 重试暂停 | 非预算，是循环保护 | 反复失败（如反复撞证据门）自动 pause | `Automatic retries paused... Send "Continue"` |
| 证据门（根因） | 内置安全门，无配置键 | 开启 | `[evidence required] bash cannot declare which files it changes...` |

**根因链**：证据门阻塞 bash 改文件 → 模型反复重试 bash → 轮数被烧光/无新进展 → 自动 pause 或轮数上限；长任务还会先撞 bedrock 的 600s 超时。

## 一、bedrock 小代码改动

1. **新迁移**（编号取当前最大 +1，模式仿 `000016`）：把 reasonix 的 `default_args` 从 `run` 更新为 `run --max-steps 400`。WHERE 条件用 `key='reasonix' AND default_args='run'`，只覆盖未自定义的值。
2. **证据门 runtime hint**（`internal/ai/service/workspace.go`）：新增 `agentEvidenceGateHint(cliKey string) string`，仅 reasonix 返回应对文案，其余 CLI 返回空；在 `agent_service.go:907` 组装处拼进 prompt（与 `agentWorkspaceScopeHint` 同风格，中英双语）。文案要点：遇 `[evidence required]` 阻塞时立即 `read_file` 列出的路径，再用 `edit_file`/`multi_edit` 修改；禁止重试 bash；禁止用 sed/patch 改未读过的文件。
3. **单测**（仿 `workspace_cli_args_test.go`）：reasonix 返回非空 hint、其他 CLI 返回空、prompt 拼接正确。
